하루 작업을 마무리하고 전체 문서를 점검한다.

## CHECK 0 — topics/ 모범 답변 줄글 재작성

**오늘 수정된** `topics/` 하위 `.md` 파일에서 **개략식 포인트 나열 형태의 모범 답변**을 찾아 **1분 이상 말할 수 있는 줄글 형태**로 재작성한다.

- 대상 파일: 오늘 수정된 파일만 (전체 topics 재작성은 토큰 낭비 — 필요하면 사용자가 `/마무리 전체`로 명시)
  - 오늘 수정 파일 찾기: `find topics -name '*.md' -newermt "$(date +%F)"`
- 대상 섹션: `모범 답변 방향`, `모범 답변`, `핵심 포인트`, `모범 답변 구조` 등
- 변환 기준:
  - bullet 나열 ❌ → 완성된 연속 문장 ✅
  - 분량: 800자 이상 (한국어 기준), 읽는 데 2분 이상
  - 작성 후 python으로 실제 글자 수 측정하여 800자 미달이면 보완 후 재저장
  - 구조: 핵심 주장 먼저 → 원리 설명 → 실무/경험 연결 → 트레이드오프
  - 경험 연결: `resume/profile.md`의 대표 프로젝트에서 관련 있는 경험만 연결 (억지 연결 금지)
- 질문 본문, 개념 설명, 코드 예시는 절대 변경하지 않는다
- 이미 줄글 형태인 모범 답변은 건너뛴다 (중복 작업 방지)

## Linter 체크 항목

`topics/` 하위의 모든 `.md` 파일을 순서대로 검사한다.

### CHECK 1 — YAML frontmatter
모든 파일 최상단에 아래 항목이 있는지 확인:
```yaml
---
tags: [...]
related: [...]
---
```
없으면 파일 내용을 분석해서 자동으로 추가한다.

### CHECK 2 — home.md 링크 누락
`home.md`에 등록되지 않은 topics 폴더가 있으면 해당 섹션에 추가한다.

### CHECK 3 — wikilink 정합성
`concepts.md` 안에서 다른 기술을 언급하지만 `[[링크]]`가 없는 경우 링크를 추가한다.

### CHECK 4 — 빈 파일
내용이 없는 `concepts.md` 또는 `questions.md` 파일 목록을 출력한다.
(자동 수정하지 않고 목록만 보여준다 — 다음 날 /오늘질문 시 우선 채울 후보)

### CHECK 5 — 단방향 링크
A → B 링크가 있는데 B → A 역링크(`related`)가 없는 경우 frontmatter의 `related` 필드에 추가한다.

### CHECK 6 — daily/ 오늘 파일 확인
오늘 날짜의 `daily/YYYY-MM-DD.md`가 있으면:
- 세션 기록이 비어있으면 (`/모의면접`을 실행하지 않은 경우) 알림
- 오늘 다룬 topics를 `## 세션 기록` 하단에 요약

### CHECK 7 — memo/ 점검
`memo/` 안의 메모 파일(`README.md` 제외)을 확인한다.
- 작성 시점: frontmatter `date` 기준, 없으면 파일명 앞 `YYYYMMDDHHmm` 기준
- **7일 이상 된 메모**: 파일마다 `이동 후보`(topics/{기술}/concepts 또는 questions) / `삭제` 중 하나를 제안하고, **사용자 확인을 받은 뒤** 처리한다
  - 이동: 해당 topics 파일에 append(중복 병합) → memo 파일 삭제
  - 삭제: 이미 topics에 있거나 가치가 없는 메모
- **7일 미만 메모**: 개수와 가장 오래된 메모의 처리 기한만 알린다 (처리하지 않음)
- 메모가 없으면 "memo 비어 있음"으로 표시

### CHECK 8 — 진행 기록 갱신 (항상 마지막에 실행)
오늘 `daily/YYYY-MM-DD.md`의 세션 기록과 CHECK 1~7 결과를 바탕으로 `progress/` 파일을 갱신한다. 파일이 없으면 빈 표 형식으로 생성한다.

**`progress/status.md`** — 오늘 `/모의면접`을 진행한 경우에만
- **기술별 준비 수준**: 오늘 다룬 기술 행을 추가하거나 갱신
  - 수준(5점): 오늘 점수(10점 만점) ÷ 2 반올림. 기존 값이 있으면 `(기존 + 오늘 환산) ÷ 2` 반올림 — 한 번의 세션으로 크게 흔들리지 않게
  - 마지막 확인: 오늘 날짜
  - 취약 포인트: 오늘 피드백에서 "보완 필요"로 나온 핵심 키워드 1~3개
- **진행 중인 공고 / 누적 세션 수**: 회사 기준 세션이면 해당 행의 세션 수 +1, 마지막 피드백 요약 갱신 (주제 연습은 `주제 연습` 행)
- **Harness 신호**: 오늘 정보를 못 찾았거나 잘못 답한 부분이 있으면 추가
- **다음 우선순위**는 수정하지 않는다 (`/주간회고`에서 재설정)

**`progress/memory.md`** — 항상
- **마지막 세션 요약**: 오늘 내용으로 덮어쓰기 (날짜, 진행 내용, 끝낸 지점, 다음 이어서 할 것 = 내일 추천 주제)
- **미결 결정사항**: 해결된 항목만 제거, 새로 생긴 항목 추가
- **인수인계 메모**: 다음 세션에 꼭 필요한 맥락만 추가

**`progress/entropy.md`** — 발견한 문제가 있을 때
- CHECK 4 빈 파일, 자동 수정하지 못한 링크·frontmatter 문제를 해당 표에 추가
- 오늘 해결한 항목은 "완료된 항목"으로 이동

## 실행 결과 출력 형식

```
## 마무리 Linter 결과 — YYYY-MM-DD

### 수정된 항목
- [파일명]: {수정 내용}

### 빈 파일 (다음 우선순위)
- topics/aws/concepts.md
- topics/elasticsearch/concepts.md
- ...

### Memo
- 기한 지남 (N개): memo/202609071030-redisson-watchdog.md → 이동 후보 topics/redis/concepts
- 대기 중 (M개): 가장 오래된 메모 처리 기한 YYYY-MM-DD

### 진행 기록 갱신
- status.md: {기술} {이전 수준} → {새 수준}, 취약 포인트 {키워드} (모의면접 없으면 "변경 없음")
- memory.md: 마지막 세션 요약 갱신
- entropy.md: {추가/완료 항목 또는 "변경 없음"}

### 오늘 요약
- 진행한 면접 세션: {횟수}회
- 다룬 주제: {기술1}, {기술2}
- 내일 추천 주제: {topics에서 가장 오래 안 다룬 기술}
```

결과 출력 후 변경된 파일들을 저장한다.

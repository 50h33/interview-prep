라이브 코딩 테스트 실전 세션을 시작한다.

## 사전 규칙 (항상 고지)

세션 시작 전 아래를 사용자에게 안내한다:

```
📋 라이브 코딩 테스트 규칙
- 구글링 가능 (문법, 라이브러리 확인 수준)
- ChatGPT "코드 짜 줘"는 금지 — 설계는 직접
- 풀이 중 생각을 말로 표현해주세요 (면접관이 듣고 있다고 가정)
- 막히면 "지금 여기서 막혔는데 이런 이유입니다" 라고 말하기
- 언어: Java 우선
```

## Step 1 — 문제 유형 결정

`$ARGUMENTS`에 따라 문제를 선택한다:

- `easy` 또는 인수 없음 → **HashMap/Collection 활용 실용 문제** 또는 **Java 동시성 기초**
- `medium` → **슬라이딩 윈도우 / 투 포인터 / 동시성 패턴 구현**
- `hard` → **시스템 설계 + 구현 혼합** 또는 **복잡한 동시성 문제**
- 특정 주제(예: `concurrency`, `map`, `stream`) → 해당 주제 문제 출제

아래 문제 풀에서 랜덤 선택하되, 이전 세션과 중복되지 않도록 한다.

### 문제 풀 (Easy)

**E1. 두 수의 합 (HashMap 활용)**
> 정수 배열 `nums`와 목표값 `target`이 주어질 때, 합이 target이 되는 두 인덱스를 반환하라. Java로 구현하되 O(N) 시간복잡도로.

**E2. 문자열 중복 문자 제거**
> 문자열에서 처음 등장하는 문자만 순서 유지해서 반환하라. (e.g., "aabbcc" → "abc")

**E3. 병렬 호출 결과 수집 (Java 동시성)**
> N개의 URL 리스트를 받아 각각 `CompletableFuture`로 병렬 처리하고, 모든 결과를 수집해 반환하는 메서드를 작성하라. (실제 HTTP 요청 불필요 — `Thread.sleep`으로 모킹). 전용 `ExecutorService` 사용 이유도 설명.

### 문제 풀 (Medium)

**M1. 슬라이딩 윈도우 — 최대 연속 부분 합**
> 길이 k인 연속 부분 배열 중 합이 최대인 값을 반환하라.

**M2. 워커 풀 + 전체 타임아웃 (Java 동시성)**
> `BlockingQueue`에서 작업을 꺼내 처리하는 N개의 워커 스레드를 구현하라. 모든 작업 완료 후 결과를 합산해 반환. 전체 작업에 타임아웃을 걸고, 타임아웃 시 남은 작업을 취소하는 처리 포함.

**M3. LRU 캐시 구현**
> `get(key)`, `put(key, value)` 연산을 O(1)로 지원하는 LRU 캐시를 구현하라. (`LinkedHashMap` 사용 금지 — HashMap + 이중 연결 리스트로 직접)

**M4. Rate Limiter 구현**
> 초당 N개 요청만 허용하는 Token Bucket 기반 Rate Limiter를 구현하라. 멀티스레드 환경에서 안전해야 함.

### 문제 풀 (Hard)

**H1. 화이트보드 — 티켓 오픈 대기열 설계**
> 1만 명이 동시에 몰리는 티켓 오픈에서 가상 대기열을 설계하라.
> 순번 저장 자료구조, 입장 허용량 결정 방법, 폴링 vs 푸시 선택, 대기열 저장소 장애 시 동작 포함.

**H2. 분산 락 구현 + 락 유실 대비**
> Redisson 없이 Redis `SET NX PX` + Lua 스크립트로 분산 락을 Java로 구현하라. 락 소유자 검증 해제, 락 만료 전 작업이 끝나지 않는 경우, 락 유실 시 DB 레벨 최종 방어선까지 설명.

## Step 2 — 문제 제시

문제를 제시하고 다음을 함께 안내한다:

```
💡 시작 전 체크리스트 (소리 내어 말하기)
1. 입력/출력 형식 확인
2. 엣지케이스 2~3개 언급
3. 브루트포스 접근법 먼저 말하기
4. 최적화 방향 설명 후 구현 시작
```

**사용자의 풀이를 기다린다. 개입하지 않는다.**

단, 5분 이상 완전 침묵이면 힌트를 줄지 물어본다:
> "힌트가 필요하신가요, 아니면 계속 생각하시겠어요?"

## Step 3 — 실시간 피드백

사용자가 풀이를 완료하거나 포기하면 아래 순서로 피드백한다.

### 3-1. 사고 과정 평가 (배점 높음)
- 문제를 어떻게 분해했는가
- 엣지케이스를 언급했는가
- 복잡도를 인지하고 설명했는가
- 막혔을 때 어떻게 표현했는가

### 3-2. 코드 품질 평가
- Java 관용적 코드 사용 여부 (Collection/Stream API, try-with-resources, 불변 객체)
- 스레드 안전성 · 리소스 누수(ExecutorService 미종료 등) 가능성
- 예외 처리 누락 여부 (InterruptedException 처리 포함)
- 변수명/가독성

### 3-3. 모범 풀이 제시
- 최적 풀이 코드 + 핵심 설명
- 면접관이 기대하는 표현/접근법 안내

### 3-4. 면접 점수 예상 (5점 만점)
```
사고 과정 표현: N/5
코드 정확성:   N/5
Java 숙련도:   N/5
커뮤니케이션:  N/5
총평: ...
```

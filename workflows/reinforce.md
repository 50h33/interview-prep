# 보강 공통 워크플로

오늘 면접에서 부족했던 키워드를 심층 정리한다. 호출 시 전달된 추가 텍스트가 있으면 우선 보완 요청으로 해석하고, 없으면 오늘 세션의 보완 필요 항목 전체를 대상으로 한다.

## Step 1 — 오늘 세션 분석

오늘의 `daily/YYYY-MM-DD.md`를 읽는다. 파일이나 완료된 면접 회차가 없으면 자료를 만들지 말고 보강할 키워드를 한 번 확인한 뒤 중단한다.

다음을 우선순위 목록으로 만든다.

1. "잘 모르겠습니다" 또는 "모름"으로 답한 개념
2. 피드백에서 미언급·오개념으로 지적된 개념
3. 추가로 알면 좋다고 언급된 개념
4. 호출 시 전달된 추가 텍스트가 있으면 그 키워드를 목록 최상단에 둔다.

## Step 2 — 심층 조사

상위 3~5개 키워드를 선택하고 사용 가능한 웹 검색·페이지 조회 도구로 다음을 조사한다.

- `{키워드} 동작 원리 상세`
- `{키워드} Java Spring 구현 예시` (구현 관련 개념일 때)
- `{키워드} 면접 답변 예시`
- `{키워드} best practices {현재연도}`

정확한 정의, 동작 원리, 사용 상황, 자주 묻는 꼬리 질문, 흔한 오개념을 수집한다. 검색 결과가 충돌하면 공식 문서와 최신 1차 자료를 우선한다. 웹 도구가 없으면 확인하지 않은 사실이나 출처를 만들지 않고, 로컬 자료로 가능한 범위만 정리하며 제한을 알린다.

## Step 3 — topics 업데이트

각 키워드의 `topics/{기술}/concepts.md`와 `questions.md`를 업데이트한다.

- 기존 내용은 덮어쓰지 않고 append한다.
- 이미 있는 내용은 중복하지 않고 필요한 부분만 보강한다.
- 외부 정보에는 출처 URL을 포함한다.
- 발표면접의 비공개 원문·노트·팀 정보·프로젝트 고유 수치는 topics에 옮기지 않는다. 프로젝트 설명 보완은 해당 `resume/`의 파생 학습 자료나 daily에 기록하고, topics에는 식별 정보를 제거한 일반 기술 지식만 정리한다.
- 코드가 도움이 되는 구현 개념이면 Java/Spring 또는 해당 기술의 표준 언어 예시를 포함한다.
- 새 파일은 `CONSTRAINTS.md`의 frontmatter, 섹션 순서, wikilink 규칙을 따른다.

`concepts.md` 추가 형식:

```markdown
## {개념명}

### 정의
{한 줄 정의}

### 동작 원리
{동작 상세와 필요한 코드/다이어그램}

### 실무 사용 시나리오
{언제, 왜 사용하는지}

### 주의할 점 / 흔한 오개념
{함정과 오해}

> 출처: {URL}
```

`questions.md` 추가 형식:

````markdown
### Q. {질문}

**핵심 답변 포인트:**
1. {포인트 1}
2. {포인트 2}

**코드 예시:** (있는 경우)
```{언어}
{코드}
```

**꼬리 질문 대비:**
- "{예상 꼬리 질문}" → {핵심 답변}

**모범 답변 구조:**
{답변 흐름}

> 출처: {URL}
````

## Step 4 — 완료 보고

보완한 키워드와 저장 위치, 키워드별 핵심 요약 2~3줄, 다음 면접에서 말할 핵심 문장을 출력한다. 설명은 실제 면접에서 말할 수준으로 유지하고 논문 수준의 세부 구현은 제외한다.

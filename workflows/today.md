# 오늘질문 공통 워크플로

오늘의 면접 질문 3개를 준비한다. 호출 시 전달된 입력은 선택적 회사명 목록으로 해석한다. 반드시 아래 순서대로 실행한다.

## 입력 처리

- **입력 있음** (예: `토스, 카카오`): 명시된 회사들의 `job.md`만 참조한다.
  - 회사명으로 `jobs/` 하위 폴더를 매핑한다. 한글 회사명과 영문 폴더명은 `job.md` frontmatter의 `company` 필드로 확인한다.
  - `_archive/` 하위는 제외한다.
- **입력 없음**: `jobs/` 하위의 모든 활성 `job.md`를 참조한다 (`_archive/` 제외).
- `resume/profile.md`가 없으면 지원자의 경험을 추측하거나 만들어내지 않는다. 프로필 기반 개인화가 제한된다고 알리고, 확인 가능한 공고와 `topics/`만으로 계속 진행한다.
- `jobs/` 또는 대상 `job.md`가 없으면 공고 내용을 만들지 않는다. 일반 모드로 진행하거나, 회사 타겟 모드를 요청했다면 자료가 없음을 명시한다.

## Step 1 — 소스 문서 파악

가능하면 다음 파일들을 동시에 읽는다.

- `resume/profile.md` — 지원자 기술 스택과 경험
- 대상 회사의 `job.md` — 공고 요구사항 및 기술 스택
- `topics/` 하위의 모든 `questions.md` — 현재 정리된 면접 질문 풀

## Step 2 — 출제 이력 확인

`daily/` 폴더가 있으면 모든 파일을 읽어 최근 출제된 질문 목록과 답변 품질을 파악한다. 폴더나 기록이 없으면 첫 출제로 간주한다.

### 잘 맞춘 질문 추적

- **잘 맞춘 질문**: 점수 6/10 이상이거나, 피드백의 "보완 필요" 항목이 핵심 개념이 아닌 세부 수준인 경우
- **재출제 필요 질문**: 점수 5/10 이하이거나, "모르겠습니다"로 답한 경우, 또는 핵심 개념(동작 원리·선택 기준·트레이드오프)이 완전히 빠진 경우

재출제 필요 질문은 기존 `daily/`에서 질문을 문자 그대로 복사한다. 단어, 조사, 조건을 바꾸지 않는다. 한국 백엔드 면접에서 실제로 검증될 가능성이 낮은 내부 구현, 수치 암기, 학술적 분류는 재출제 판단에서 제외한다.

**가중치 규칙:**

- 같은 질문이나 실질적으로 같은 내용을 2회 이상 잘 맞춘 경우 오늘 목록에서 제외하고 같은 토픽의 다른 각도 질문으로 대체한다.
- 잘 맞춘 질문이 많은 토픽은 아직 다루지 않은 심화 질문으로 교체한다.
- 재출제 필요 질문은 가중치를 높인다.

**일반 모드:**

- 최근 7일 이내 출제 질문은 제외한다. 단, 재출제 필요 질문은 예외다.
- 같은 주제가 3일 연속 나오지 않게 한다.
- 아직 다루지 않은 topics 폴더가 있으면 우선한다.

**회사 타겟 모드:**

- 중복·연속 제한을 적용하지 않고 해당 회사에서 나올 가능성을 최우선으로 본다.
- 잘 맞춘 질문도 공고 핵심 기술이면 더 심화된 각도로 출제할 수 있다.
- 출제 이력은 같은 질문의 그대로 반복을 피하는 참고 자료로 사용한다.

## Step 3 — 최신 트렌드 보강

사용 가능한 웹 검색 도구로 다음을 확인한다.

- `백엔드 개발자 면접 최신 트렌드 {현재연도}`
- 대상 공고 기술 중 최근 이슈나 변경사항

웹 검색을 사용할 수 없으면 이 단계를 건너뛰고, 확인하지 않은 최신 정보나 출처를 만들지 않는다. 결과에서 이 제한을 짧게 알린다.

## Step 4 — 오늘의 질문 3개 선정

구성은 **기초 2개 + 중급 1개**다.

회사명이 지정된 경우 공고의 기술 스택과 우대 사항을 우선한다. 복수 회사면 공통 기술의 가중치를 높이고 회사별 특이 스택도 반영한다.

### 회사 기술 스택 필터

- `job.md` 기술 스택에 없는 언어·프레임워크 질문은 제외한다.
- 공고 기술 스택이 불명확하면 존재하는 `resume/profile.md`의 기술 스택을 기준으로 한다.
- 범용 백엔드 지식(네트워킹, 분산 시스템, 시스템 설계)은 스택 제한 없이 출제할 수 있다.

### 이력서 연계 필터

프로필이 있을 때만 다음을 적용한다.

- 이력서 기술은 실제로 이해하고 사용하는지 확인하는 관점으로 묻는다.
- 대표 성과와 자연스럽게 연결할 수 있으면 질문에 경험 연결 요청을 포함한다.
- 이력서에 없지만 공고에 있는 기술은 개념 수준 설명 관점으로 묻는다.

### 질문 현실성 필터

- 런타임·컴파일러 내부 구현, 어셈블리 수준, 출제 가능성이 낮은 학술 질문은 제외한다.
- 개념 정의, 블랙박스 수준의 원리, 트레이드오프, 실무 패턴, 장애 대응과 선택 판단을 우선한다.

### 기초 2개

1. 서로 다른 topic에서 고른다.
2. 기술을 쓴다고 했을 때 기본 개념을 아는지 검증한다.
3. 확인된 실무 기술을 우선하되 경험이 없어도 개념 수준으로 답할 수 있어야 한다.
4. 공고 필수 스택 중 기초를 아직 다루지 않은 것을 우선한다.

### 중급 1개

1. 이전 기록의 "다음에 집중할 주제"를 우선한다.
2. 꼬리 질문에서 "모르겠습니다"로 답한 항목을 우선한다.
3. 공고 우대 역량을 반영한다.

각 질문에는 질문 본문, 관련 topic wikilink, 난이도, 출제 의도, 회사 타겟 모드일 때 대상 회사를 기록한다.

## Step 5 — daily 기록

오늘 날짜의 `daily/YYYY-MM-DD.md`를 사용한다. 파일이 없으면 아래 형식으로 생성한다. 파일이 이미 있으면 기존 질문, 답변, 세션 기록을 절대 덮어쓰지 않는다. 이미 `## 오늘의 질문`이 있다면 재실행 사실과 새 질문 세트를 구분하는 새 하위 섹션을 append하거나, 기존 질문이 그대로 유효하면 변경 없이 재출력한다.

```markdown
---
date: YYYY-MM-DD
topics: [기술1, 기술2, ...]
session: {회사명 또는 null}
---

# YYYY-MM-DD 면접 준비

> 대상 공고: {회사명 목록 또는 "전체"}

## 오늘의 질문

### [기초] Q1. {질문}
- 관련 토픽: [[topics/{기술}/questions]]
- 난이도: 기초
- 출제 의도: {한 줄 설명}

### [기초] Q2. {질문}
- 관련 토픽: [[topics/{기술}/questions]]
- 난이도: 기초
- 출제 의도: {한 줄 설명}

### [중급] Q3. {질문}
- 관련 토픽: [[topics/{기술}/questions]]
- 난이도: 중급
- 출제 의도: {한 줄 설명}

## 세션 기록
<!-- 모의면접 실행 후 결과가 여기에 추가됨 -->
```

저장 후 오늘의 질문 3개를 대화창에 출력한다.

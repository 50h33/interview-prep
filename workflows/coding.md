# 코딩테스트 공통 워크플로

Java 중심 라이브 코딩·화이트보드 연습을 진행한다. 호출 입력은 선택적 주제 또는 `easy`, `medium`, `hard` 난이도다.

## 시작 안내

구글링은 문법·라이브러리 확인 수준에서 가능하고 설계와 구현은 사용자가 직접 한다. 생각을 소리 내어 설명하고, 막힌 지점과 이유도 말하도록 안내한다. Java를 우선한다.

## Step 1 — 문제 선택

- `easy` 또는 입력 없음: HashMap·Collection 실용 문제 또는 Java 동시성 기초
- `medium`: 슬라이딩 윈도우·투 포인터 또는 동시성 패턴 구현
- `hard`: 시스템 설계와 구현 혼합 또는 복잡한 동시성
- 특정 주제: 해당 주제 문제

이전 기록과 중복되지 않게 아래 풀에서 선택한다.

### Easy

- 두 수의 합: 정수 배열과 target에서 합이 target인 두 인덱스를 HashMap으로 O(N)에 반환한다.
- 문자열 중복 문자 제거: `"aabbcc" → "abc"`처럼 처음 등장 순서를 유지한다.
- 병렬 호출 결과 수집: N개 URL을 전용 `ExecutorService`와 `CompletableFuture`로 병렬 처리해 모두 수집한다. 실제 HTTP 요청은 하지 않고 `Thread.sleep`으로 모킹하며, 전용 `ExecutorService`를 쓰는 이유도 설명한다.

### Medium

- 길이 k인 연속 부분 배열 중 최대 합을 구한다.
- `BlockingQueue`의 작업을 N개 워커가 처리하고 결과를 합산한다. 전체 타임아웃과 남은 작업 취소를 포함한다.
- `LinkedHashMap` 사용 없이 HashMap과 이중 연결 리스트로 `get`, `put` O(1) LRU 캐시를 구현한다.
- 초당 N개 요청을 허용하는 멀티스레드 안전 Token Bucket Rate Limiter를 구현한다.

### Hard

- 1만 명이 동시에 몰리는 티켓 오픈 가상 대기열: 순번 자료구조, 입장 허용량, 폴링과 푸시 선택, 저장소 장애 시 동작을 포함한다.
- Redisson 없이 Redis `SET NX PX`와 Lua로 분산 락을 구현한다. 소유자 검증 해제, 락 만료 전에 작업이 끝나지 않을 때의 처리, 락 유실 시 DB 방어선을 설명한다.

## Step 2 — 문제 제시와 대기

문제와 함께 입력·출력, 엣지케이스 2~3개, 브루트포스, 최적화 방향을 소리 내어 설명하도록 안내한다. 문제는 한 번에 하나만 제시하고 사용자 풀이를 기다린다. 사용자가 응답하는 동안 선제적으로 정답이나 힌트를 주지 않는다. 사용자가 막혔다고 말하거나 힌트를 요청하면 필요한 수준을 확인해 단계적으로 제공한다. 대화 환경에서 실제로 5분 이상 완전 침묵을 확인할 수 있을 때는 "힌트가 필요하신가요, 아니면 계속 생각하시겠어요?"라고 묻는다.

## Step 3 — 피드백

완료 또는 포기 후 다음을 평가한다.

1. 문제 분해, 엣지케이스, 복잡도 인지, 막혔을 때의 표현
2. Java 관용구, 스레드 안전성, ExecutorService 등 자원 종료, 예외와 interruption 처리, 가독성
3. 최적 풀이 코드와 면접관이 기대하는 접근 표현

점수는 사고 과정 표현, 코드 정확성, Java 숙련도, 커뮤니케이션을 각각 5점 만점으로 제시하고 총평을 남긴다.

## Step 4 — 다음 문제

피드백 뒤 같은 난이도, 한 단계 위, 종료 중 선택을 한 번 묻고 답변을 기다린다. 종료하면 세션 요약과 다음에 집중할 패턴 1~2개를 안내한다.

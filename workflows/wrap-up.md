# 마무리 공통 워크플로

하루 작업을 마무리하고 Knowledge Graph와 진행 기록을 점검한다. 호출 입력이 `전체`일 때만 오늘 수정 파일 제한을 해제한다.

## CHECK 0 — 오늘 수정된 topics 모범 답변

기본 대상은 실행 환경의 로컬 날짜 기준 오늘 수정된 `topics/**/*.md`다. 파일의 수정 시각을 기준으로 다음 명령에서 얻은 목록을 먼저 확정한 뒤 내용을 고친다.

```text
python scripts/vault_tools.py changed-topics --date YYYY-MM-DD --root .
```

`전체` 입력일 때만 모든 topics 문서를 검사한다. 개략식 포인트 나열 형태의 모범 답변을 800자 이상 말하기 줄글로 재작성한다. 핵심 주장, 원리, 확인된 경험과의 자연스러운 연결, 트레이드오프 순서를 사용한다. 프로필이 없거나 관련 경험이 없으면 경험을 만들지 않는다. 질문 본문, 개념 설명, 코드 예시는 변경하지 않고 이미 줄글인 답변은 건너뛴다.

말하기 본문만 UTF-8 임시 파일에 저장해 다음 명령으로 측정하고, 800자 미만이면 보강 후 재측정한다.

```text
python scripts/vault_tools.py count-text <UTF8파일>
```

사용자 문자열을 셸 명령에 직접 보간하지 않는다.

## CHECK 1~7 — 구조 검사

1. 모든 topics 파일 최상단의 `tags`, `related` frontmatter를 확인하고 없으면 내용에 근거해 추가한다.
2. `home.md`에 없는 topics 폴더를 해당 섹션에 연결한다.
3. 다른 기술을 언급하지만 링크가 없는 곳에 유효한 전체 경로 wikilink를 추가한다.
4. 내용이 없는 `concepts.md` 또는 `questions.md`는 자동 작성하지 않고 목록만 출력한다.
5. A→B 링크가 있으나 B의 `related`에 A가 없으면 역링크를 추가한다.
6. 오늘 daily가 있으면 세션 기록이 비었는지 알리고, 실제로 다룬 topics를 세션 기록 하단에 요약한다.
7. `memo/`의 메모를 확인하되 `memo/README.md`는 제외한다. 작성 시점은 frontmatter의 `date`, 없으면 파일명 앞 `YYYYMMDDHHmm`를 사용한다. 7일 미만은 개수와 가장 오래된 처리 기한만 알린다. 7일 이상은 각 파일의 이동 후보 또는 삭제를 판단한다. 현재 대화에서 해당 처리의 명시적 요청이나 확인이 없으면 먼저 제안하고 답변을 기다린다. 이미 확인받았으면 반복 확인 없이 처리한다. 이동 시 topics에 중복 없이 append한 다음 memo를 삭제한다.

## CHECK 8 — 진행 기록과 중복 방지 ledger

마지막에 `progress/status.md`, `memory.md`, 필요하면 `entropy.md`를 갱신한다. 없는 파일은 프로젝트의 빈 표 형식으로 생성한다.

### 완료 회차 식별

면접 회차 ID는 `YYYY-MM-DD#N`이다. `daily/YYYY-MM-DD.md`에서 `## 세션 기록 (N회차)`와 그 회차 끝의 `<!-- interview-complete -->`가 모두 있는 회차만 완료로 본다.

`progress/status.md`에 다음 표를 유지한다. 이미 같은 ID가 있으면 세션 수, 준비 수준, 점수를 다시 반영하지 않는다.

```markdown
## 반영 완료 면접 회차

| 회차 ID | 반영일 | 반영 워크플로 |
|---|---|---|
| YYYY-MM-DD#N | YYYY-MM-DD | 마무리 또는 주간회고 |
```

오늘의 완료 회차 중 ledger에 없는 회차만 반영한다. 여러 회차는 회차 ID의 날짜와 N 오름차순으로 하나씩 적용한다. 한 회차의 기술별 수준·누적 세션 수를 계산한 뒤 같은 저장 작업에서 해당 ID를 ledger에 추가한다. 상태 갱신과 ledger 추가 중 하나만 저장하지 않는다. 저장 직전 다시 ledger를 확인해 중복을 막는다.

완료 표식이 없는 legacy 회차는 과거 집계 여부를 확정할 수 없으므로 자동 재가산하지 않는다. 실제 Q&A 전문, 질문별 점수, 회차 총평이 모두 있는 기록에 한해서만 해당 ID와 "기존 집계 여부 불명"을 안내한다. 사용자가 그 완성된 회차가 미반영이라고 명시적으로 확인한 경우에만 한 번 반영해 ledger에 기록한다. 하나라도 빠진 회차는 미완성으로 유지하며 완료나 점수를 가정하지 않는다.

### status.md 반영 규칙

- 새 완료 회차가 있을 때만 기술별 준비 수준과 누적 세션 수를 갱신한다.
- 한 회차에서 같은 기술 질문이 여러 개면 그 기술의 질문별 기본 점수 평균을 구한 뒤 2로 나누고, 가장 가까운 정수로 반올림하되 정확히 `.5`이면 올림한다. 보너스는 수준 환산에서 제외한다.
- 기존 수준이 있으면 `(기존 수준 + 새 회차 환산 수준) / 2`를 같은 방식으로 `.5` 올림 반올림한다. Python의 기본 `round`처럼 짝수 쪽으로 보내는 반올림은 사용하지 않는다.
- 누적 세션 수는 완료 회차마다 회차 메타의 `대상 회사`에 1을 더한다. 회차 메타가 없는 이전 기록만 daily frontmatter의 `session`을 참고한다. 둘 다 없거나 분명하지 않으면 회사를 만들어내지 않고 `주제 연습`으로 분류한다. 질문 수나 기술 수만큼 올리지 않는다.
- 마지막 확인, 핵심 취약 포인트 1~3개, 회사 또는 `주제 연습` 행의 마지막 피드백을 갱신한다.
- 정보를 못 찾았거나 잘못 답한 부분은 Harness 신호에 추가한다.
- 다음 우선순위는 변경하지 않는다. 주간회고가 담당한다.

### memory.md와 entropy.md

- memory는 날짜, 진행 내용, 끝낸 지점, 다음 이어서 할 내용으로 마지막 세션 요약을 갱신한다. 해결된 미결 항목을 제거하고 필요한 인수인계만 남긴다.
- entropy는 빈 파일, 자동 수정하지 못한 링크·frontmatter 문제를 추가하고 해결 항목을 완료로 이동한다.

## 결과

수정한 파일별 변경 내용, 빈 파일 목록, 기한 지난 memo와 대기 memo 수·가장 오래된 처리 기한, status의 기술별 변경 전후·취약 포인트와 새로 ledger에 기록한 회차 ID, memory·entropy 변경, 오늘 완료 세션 수·주제·내일 추천 주제를 보고한다. 새 회차가 없으면 세션 수와 수준이 변경되지 않았음을 명시한다.

# 모의면접 공통 워크플로

호출 시 전달된 선택적 입력을 특정 주제 또는 회사명으로 해석하고 실전 면접 세션을 시작한다.

사용자가 프로젝트 발표자료나 발표자 노트를 기반으로 연습을 요청했다면 먼저 [발표면접](./presentation.md)으로 진행한다. 발표면접에서 이 문서를 참조하는 경우에는 다시 라우팅하지 않고 그 문서가 지정한 진행·채점·기록 절차만 적용한다.

## Step 1 — 질문 불러오기

입력이 있으면 다음 순서로 소스를 찾는다.

1. `jobs/` 아래에서 이름이나 `job.md`의 `company`가 입력과 맞는 회사를 찾아 기술 스택 기반 질문을 선택한다.
2. `topics/{입력}/questions.md`가 있으면 해당 파일에서 선택한다.
3. 관련 topics 파일에서 입력 키워드를 검색한다.
4. 소스를 찾지 못하면 주제를 한 번만 확인하고 중단한다. 자료를 만들어내지 않는다.

질문이 여러 개면 난이도 순(기초→중급→심화)으로 3개를 선택하고, 3개 미만이면 있는 만큼만 진행한다. topic 또는 회사 입력으로 시작해 오늘 daily가 없으면 면접을 시작하기 전에 `CONSTRAINTS.md`의 daily frontmatter(`date`, `topics`, `session`)와 날짜 제목을 갖춘 `daily/YYYY-MM-DD.md`를 생성한다. 확인한 주제와 회사를 기록하며 회사가 없으면 `session: null`을 사용한다. 기존 daily가 있으면 내용을 덮어쓰지 않고 이후 기록만 append한다.

입력이 없으면 오늘의 `daily/YYYY-MM-DD.md`에서 아직 세션 기록에 등장하지 않은 질문 중 최대 3개를 무작위로 선택한다. 원래 Q 번호 순으로 뽑거나 제시하지 않는다. 기초·중급 비율은 섞어도 된다. 파일 또는 질문이 없으면 오늘질문 워크플로를 먼저 실행하도록 안내하고 변경 없이 중단한다.

`resume/profile.md`가 없으면 경험을 추측하지 않고 프로필 연계 평가만 생략한다고 알린 뒤 진행한다.

## Step 2 — 면접 진행

- 질문은 한 번에 하나만 제시하고 매번 사용자 답변을 기다린다.
- 실제 면접관처럼 자연스럽게 진행한다.
- 한 답변에서 빠진 핵심이 있으면 꼬리 질문으로 유도하되 최대 3개다.
- 핵심 요소 80% 이상이면 0~1개, 50~79%면 2~3개, 50% 미만이면 최대 3개를 사용한다.
- 꼬리 질문은 빠진 핵심 키워드, 실무 적용·트레이드오프 순으로 묻고 같은 난이도 안에 머문다.
- 런타임 내부 구현, 컴파일러, 어셈블리 수준처럼 일반 백엔드 면접에서 묻지 않을 질문은 금지한다.

각 질문은 `질문 → 답변 대기 → 필요한 꼬리 질문과 각 답변 대기 → 피드백 → 다음 질문` 순서다.

### 피드백

- 프로필이 있을 때만 확인된 이력서 경험과 연결해 평가한다.
- 잘한 점을 먼저 말하고, 보완할 점은 구체적인 키워드·코드·문장으로 제시한다.
- 수치나 결론을 첫 문장에 두고 구조 설명과 기술 세부 사항으로 이어지는 답변을 안내한다.
- STAR 또는 문제-해결-성과 구조를 활용한다.
- 보완 사항은 동작 원리, 트레이드오프, 실무 패턴, 선택 기준 중 핵심 최대 3개만 남긴다. 내부 구현, 수치 암기, 학술적 분류는 제외한다.
- 6/10 이상 답변은 보완 사항을 1~2개로 제한한다.

### 모범 답변 분량 검증

모범 답변은 개략식 목록이 아닌 실제 말하기 형태의 완성된 문장으로 **800자 이상** 작성한다. 핵심 주장, 원리, 확인된 경험과의 연결, 트레이드오프와 결론을 포함한다. 경험 자료가 없으면 경험을 만들지 않는다.

말하기 본문만 UTF-8 임시 파일에 저장하고 다음 명령으로 글자 수를 측정한다. 셸 명령에 사용자 답변을 직접 보간하지 않는다. 800자 미만이면 보강 후 재측정한다.

```text
python scripts/vault_tools.py count-text <UTF8파일>
```

이 명령은 CRLF를 LF로 정규화하고 마지막 줄바꿈을 제외해 센다. 검증 후 임시 파일을 정리한다.

### 채점

| 항목 | 배점 | 기준 |
|---|---:|---|
| 핵심 키워드 커버율 | 5점 | 모범 답변의 핵심 키워드 커버 |
| 답변 구조 | 3점 | 결론이 명확하고 흐름이 논리적임 |
| 꼬리 질문 대응 | 2점 | 올바른 답변, 꼬리 질문이 없으면 자동 2점 |
| 실무 경험 연결 | +1점 | 확인된 경험과 자연스럽게 연결한 보너스 |

질문당 기본 10점, 보너스 포함 최대 11점이다. 3문제 세션은 기본 `N/30`, 보너스 포함 최대 33점으로 합산한다. 질문이 3개 미만이면 기본 분모를 `진행 질문 수 × 10`으로 명시한다.

## Step 3 — 세션 종료 후 기록

### 회차 결정과 완료 조건

오늘 파일의 `## 세션 기록 (N회차)` 번호를 모두 읽고 **가장 큰 N + 1**을 새 회차로 사용한다. 섹션 수로 번호를 정하지 않는다. 세션 진행 중에는 완료 표식을 쓰지 않는다. 모든 질문의 답변·피드백·점수·총평까지 저장된 회차 마지막에 다음 표식을 한 번만 추가한다.

```markdown
<!-- interview-complete -->
```

도구 전환 시 완료 표식이 없는 회차는 불완전 기록으로 취급한다. 파일에 실제 저장된 문답만 복구하고 저장되지 않은 대화를 추측하지 않는다.

### daily 전문 append

기존 내용을 보존하고 다음 형식으로 append한다.

```markdown
## 세션 기록 ({N}회차)

- 회차 주제: {이번 회차에서 다룬 topics 목록}
- 대상 회사: {확인된 회사명 또는 null}
- 집계 대상: {회사명 또는 주제 연습}

### Q1. {실제로 질문한 완성 문장 전문}

**답변:**
{사용자 답변 전문}

**꼬리 질문:** {실제 꼬리 질문 또는 없음}

**꼬리 답변:**
{사용자 답변 전문 또는 없음}

**피드백:**
- 잘한 점: {구체적 내용}
- 보완 필요:
  - {핵심 보완 사항}
- 점수: {N}/10 (보너스: +{0 또는 1})
  - 핵심 키워드: {n}/5 ({미언급 키워드})
  - 답변 구조: {n}/3 ({이유})
  - 꼬리 질문: {n}/2
  - 실무 경험 보너스: +{0 또는 1} ({확인된 경험 또는 "미연결"})
- 모범 답변 ({실제 측정 글자 수}자):
  > {800자 이상 말하기 형태의 답변}
- 관련 개념 상세: [[topics/{기술}/questions#{섹션}]] | [[topics/{기술}/concepts#{섹션}]]

---

### Q2. ...

---

**오늘의 총평**: {전반적인 강점과 공통 보완 패턴}
**세션 총점**: {합산}/{기본 만점} ({백분율}%, 보너스 별도 표기)
**다음에 집중할 주제**: {우선순위 기술명}

<!-- interview-complete -->
```

### topics Feedback Loop

세션에서 나온 새 개념은 `concepts.md`, 새 질문과 꼬리 질문 및 모범 답변 포인트는 `questions.md`에 append한다. 기존 내용을 덮어쓰거나 중복 추가하지 않는다. 외부 정보를 더하면 출처 링크를 포함한다.

각 daily Q&A 피드백 하단에는 실제 섹션을 가리키는 전체 경로 wikilink를 넣는다. 여러 topics면 `|`로 구분한다.
